# oxlint-config

- A preset takes a rule only when it catches a bug or a security hole that `correctness` misses, or code that misleads its reader, such as a cast that changes nothing. It takes it only once the code shape the rule forces is right. A hit in a consumer is a sign about that consumer's design, not a reason to drop the rule. A style rule enters only where the standard sets that style, as code-style.md does for braces and file length.
- A rule a preset turns off carries a comment with the reason. A consumer's config holds only exceptions about its own files or names.
- `solid.json` follows eslint-plugin-solid's recommended set, plus the plugin's rules for Solid 1 bugs that set leaves out, its rule against reactive state at module scope, which bypasses the composition root, and the `jsx-a11y` correctness rules.
- `layers.json` turns on `kk-forge/layers` and `kk-forge/environment`. `layers` holds the layer table itself, since oxlint drops `settings` that come through `extends`. A change to either rule adds a breaking `bad-*` file under `test/layers/src`, or under `test/layers/tests` for what `layers` checks in tests. A file that breaks `environment` is named `bad-env-*`. What `layers` and `environment` check between apps and packages goes in `test/monorepo` the same way, and a case that must stay silent outside a monorepo goes in `test/standalone`, which holds no `bad-*` file. A feature's surface reports in its `exports.ts` and its use cases file, which a `bad-*` name cannot mark, so those cases sit in `test/consumer`.
- Each preset owns one concern: `typescript.json` the language, `vitest.json` the tests, `solid.json` Solid and JSX, `wxt.json` WXT entrypoints, `solid-start.json` SolidStart's launchers, `layers.json` the architecture. A rule goes in the preset whose concern it checks, and each preset works alone or with any other.
- `wxt.json` turns on `kk-forge/wxt-entrypoint-folder`, and `kk-forge/launcher` in place of `kk-forge/no-index-files` for `**/entrypoints/*/index.ts{,x}`. `solid-start.json` turns on `kk-forge/launcher` for `src/app.tsx`, `src/entry-client.tsx`, `src/entry-server.tsx` and the files under a `routes` folder, tests aside. It sets the rule's option `defaultExport`, which also takes a default export of one call or of an imported name. `solid.json` turns on `kk-forge/no-conditional-map` and `kk-forge/no-inline-svg`. `typescript.json` turns on `kk-forge/no-index-files` and `kk-forge/no-html-key`, and its override for tests turns `no-html-key` off.
- The plugin `kk-forge` holds the rules `environment`, `launcher`, `layers`, `no-conditional-map`, `no-html-key`, `no-index-files`, `no-inline-svg` and `wxt-entrypoint-folder`. Its source is `src/plugin.ts` with one file per rule, and `mise run build` compiles it into `dist/`, which the package ships. `layers` and `environment` import `src/places.ts`, which places a path in its layer. It resolves an alias through `src/tsconfig.ts`, which reads the nearest tsconfig.json's `paths`. `layers` also imports `src/module-counts.ts`, which counts the imports between modules, and `src/feature-surface.ts`, which judges a feature's surface by the declarations `src/exported-names.ts` follows each export to. It imports `src/repository.ts` too, which judges the imports between a monorepo's apps and packages and counts the apps each package serves, `src/package-modules.ts`, which holds the modules inside a package's layer module to their `exports.ts`, and `src/platforms.ts`, which holds each platform's SDK to its adapter, that adapter to the entrypoints of its runtime, and each entrypoint to one platform. `environment` holds each platform's global APIs to its adapter. For a named workspace package import, the first subpath segment selects the layer. Its platform adapter is a surface of its own and counts toward the importing entrypoint’s platform, including imports read from disk. Both read the platforms from one table in `src/platforms.ts`, one record per platform: its adapter folder under `infra`, its SDK's package names and prefixes, its globals, the members that read the interface strings, and the entry API an entrypoint may take with the modules that re-export it. Nothing outside that record names a platform, so a new platform is one entry, and `layers.json` stays the one preset that checks them. `environment` asks `src/repository.ts` whether a file sits in a package. `layers` and `environment` ask `src/scope.ts` whether a name is the global. `layers`, `environment` and `no-html-key` read a string or a key as written through `src/literals.ts`. `src/module-counts.ts`, `src/repository.ts` and `src/platforms.ts` read imports from disk through `src/imports.ts`, and `src/recent.ts` keeps what they read for a second. A rule matches exactly and never guesses: it reads the parsed program, the scope a reference resolves in and the repository's layout, and a regular expression only where it names a known set. Every preset that turns on one of its rules loads `dist/plugin.js`, and a config that extends several reports each problem once. git keeps the source only, so `mise run lint` builds first.
- `layers` and `environment` export `newLayersRule` and `newEnvironmentRule`, which build the rule over a list of platforms, the table by default. `test/platforms-plugin.ts` builds both over the table plus a test platform, `electron`, from the compiled `dist/`, whose declarations `tsconfig.build.json` emits. `test/platforms` is its fixture, named `bad-*` and `bad-env-*` as `test/layers` is, and `test/configs.test.ts` runs it, so a change to the platform checks keeps a test platform getting each of them. The test platform ships in no preset.
- `test/consumer` is a WXT app with Solid that extends every preset but `vitest.json`. `test/solid-start` is a SolidStart app that extends `typescript.json`, `solid.json` and `solid-start.json`, and holds the launcher cases SolidStart's files make. A change to a `kk-forge` rule outside `layers.json` adds a file to `test/consumer` or `test/solid-start`, named `bad-*` or in a `bad-*` folder when it breaks the rule, and the list in `test/configs.test.ts` names each report.
- A change to an oxlint or eslint-plugin-solid rule in the presets adds a breaking line to `test/fixtures/Broken.tsx`, or to `Broken.test.tsx` for `vitest.json`, and the rule to `test/configs.test.ts`. A rule that judges a whole file or its path, such as `max-lines` or the logger's `no-console` exception, gets a fixture file of its own. `mise run check` runs it.
- A peer dependency names the lowest version that has every rule the presets turn on, so a consumer need not upgrade its linter further than the rules need. `mise run test:peer-floors` tests on those versions, and CI runs it beside the test on the newest. oxlint 1.90 and oxlint-tsgolint 7.0.2005 add `typescript/no-unsafe-enum-assignment`, and eslint-plugin-solid 0.19 adds `solid/no-unassigned-vars` and `solid/validate-jsx-nesting`.
- A change that fails code the last release passed, a new rule included, raises the major version.
