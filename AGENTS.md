# oxlint-config

- A preset takes a rule only when it catches a bug or a security hole that `correctness` misses, or code that misleads its reader, such as a cast that changes nothing. It takes it only once the code shape the rule forces is right. A hit in a consumer is a sign about that consumer's design, not a reason to drop the rule. No style rules.
- A rule a preset turns off carries a comment with the reason. A consumer's config holds only exceptions about its own files or names.
- `solid.json` follows eslint-plugin-solid's recommended set, plus the plugin's rules for Solid 1 bugs that set leaves out, and the `jsx-a11y` correctness rules.
- `layers.json` turns on `kk-forge/layers`. The rule holds the layer table itself, since oxlint drops `settings` that come through `extends`. A rule change adds a breaking `bad-*` file under `test/layers/src`, or under `test/layers/tests` for what it checks in tests.
- `wxt.json` turns on `kk-forge/wxt-entrypoint-folder`, and `kk-forge/launcher` in place of `kk-forge/no-index-files` for `**/entrypoints/*/index.ts{,x}`. `solid.json` turns on `kk-forge/no-conditional-map`.
- The plugin `kk-forge` holds the rules `launcher`, `layers`, `no-conditional-map`, `no-index-files` and `wxt-entrypoint-folder`. Its source is `src/plugin.ts` with one file per rule, and `mise run build` compiles it into `dist/`, which the package ships. Every preset that turns on one of its rules loads `dist/plugin.js`, and a config that extends several reports each problem once. git keeps the source only, so `mise run lint` builds first.
- `test/consumer` is a WXT app with Solid that extends all four presets. A change to a `kk-forge` rule other than `layers` adds a file there, named `bad-*` or in a `bad-*` folder when it breaks the rule, and the list in `test/configs.test.ts` names each report.
- A change to an oxlint or eslint-plugin-solid rule in the presets adds a breaking line to `test/fixtures/Broken.tsx` and the rule to `test/configs.test.ts`. `mise run check` runs it.
